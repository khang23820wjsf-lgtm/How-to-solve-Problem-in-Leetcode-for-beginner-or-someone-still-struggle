# Problem 7 - Reverse Integer

- Given a signed 32-bit integer x, return x with its digits reversed.
- If reversing x causes the value to go outside the signed 32-bit integer range [-2^31, 2^31 - 1], then return 0.

### Example 1:
```
Input: x = 123
Output: 321
```

### Example 2:
```
Input: x = -123
Output: -321
```

### Example 3:
```
Input: x = 120
Output: 21
```

---

## How to solve this problem?

We will use math :))))) because it's easy to learn and you can fix it easily

There are 5 steps to solve it

### Step 1:

We must check x if it positive ok but if its negative we will need to use a variable name "Sign" so you can turn the number you just reversed into a negative number.

Just use if

```python
if x>0:
    sign = 1
else:
    sign = -1
```

We will turn x into an absolute value

```python
x = abs(x)
```

### Step 2:

We will use loop while to check until x = 0:

For example:

You see x = 342

```
342 -> 34 -> 3 -> 0
```

We dont't have anything left to check

### Step 3:

How to get the last digit easily?

We will use : digit = x%10 (% is the modulo operator)

### Step 4:

How to turn it into an number?

we will create a variable name "Result" start at 0:

In "While" loop we will use the formula : result = result*10+digit

Why multiply 10?

Because multiplying by 10 shifts every existing digit one position to the left, creating space for the new digit.

For example:

342

We have 2:
```
result = 0*10+2
```
Then we have 4:
```
result = 2*10+4
```
Finally, we have 3:
```
result = 24*10+3
```
=> result = 243

### Step 5:

After we get a digit, we will need to the next digit:

So we will use : x//=10

For example:
```
342 -> 34 -> 3 -> 0
```

### After completing step 2 -> 4:

We will have:

```python
While x>0:
    digit = x%10
    result = result *10 + digit
    x//= 10
```

Completing all step above we'll have result:

We will do: result = result * sign just to make sure if it has to have the correct positive or negative sign from the start

After all we just need to do some basic if

```python
if result >= -2^31 and result<= 2^31-1:
    return result
else:
    return 0
```

## Code

### Python

```python
class Solution:
    def reverse(self, x: int) -> int:
        if x > 0:
            sign = 1
        else:
            sign = -1

        x = abs(x)
        result = 0

        while x > 0:
            digit = x % 10
            result = result * 10 + digit
            x //= 10

        result *= sign

        if result >= -2**31 and result <= 2**31 - 1:
            return result
        else:
            return 0
```

var reverse = function(x) {
    let sign = x > 0 ? 1 : -1;
    let xAbs = Math.abs(x);
    let result = 0;

    while (xAbs > 0) {
        let digit = xAbs % 10;
        result = result * 10 + digit;
        xAbs = Math.floor(xAbs / 10);
    }

    result *= sign;

    if (result >= -(2 ** 31) && result <= 2 ** 31 - 1) {
        return result;
    } else {
        return 0;
    }
};

class Solution {
    public int reverse(int x) {
        int sign = x > 0 ? 1 : -1;
        long xAbs = Math.abs((long) x);
        long result = 0;

        while (xAbs > 0) {
            long digit = xAbs % 10;
            result = result * 10 + digit;

## Overall

| Item | Detail |
|---|---|
| **Core idea** | Peel off digits one at a time using `% 10`, rebuild the reversed number using `result * 10 + digit`, drop the used digit using `// 10` (or `/ 10` depending on language) |
| **Sign handling** | Separate the sign into a `sign` variable and work with the absolute value, then multiply the sign back in at the end |
| **Loop stop condition** | When `x = 0` (no digits left to process) |
| **Overflow check** | Compare the final `result` against the range `[-2^31, 2^31 - 1]` — if it goes outside, return `0` |
| **Time complexity** | `O(log₁₀ x)` — the number of loop iterations equals the number of digits in `x` |
| **Space complexity** | `O(1)` — only a few extra variables are used (`sign`, `digit`, `result`) |
| **Note for C++/Java** | Use `long` when accumulating `result` to avoid overflowing before you get the chance to check the range, since a 32-bit `int` can overflow mid-calculation |
| **Why this approach is nice** | No need to convert `x` to a string — it's pure math, so it's easy to follow, easy to debug, and portable across most programming languages |
